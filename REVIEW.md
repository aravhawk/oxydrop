**Leakage/tuning verdict.** The executable fixed-protocol evaluation holds both hands out together and fits scaling only on training people. Calibration uses the held-out person's own initial minute without labels; that is personalization, not person leakage. No future-record median or `filtfilt` appears in the current scored feature path. However, **“every setting chosen on the other five” is unsupported for the research arrays and false as a blanket description of v2**: `chain.py` describes C as the earlier nested-CV modal choice, v2 hardcodes it, and the band's claimed advance selection has no independent provenance. Comparing many variants on the same six people is test-set reuse even with correct person splits. BUT cross-fitting does hold subjects out, but final gate choice uses both halves' acceptance; the pooled cross-fit score is not an untouched test of that final fixed gate. `BEAT_AGREE=.12` and `SAT_MAX=.10` remain heuristics.

**Missing baselines/controls.** Always predicting the majority class gives **57.48%** accuracy. On the **same 3,836 windows v2 answers**, v1 already scores **94.60%**, versus v2 **94.68%**: the headline selective gain is mostly selection, not demonstrated better classification. Publish matched-coverage curves, person-level alert yield, HR-only rules and a reproduced Hoffman CNN/ratio baseline under identical labels/calibration/abstention. Current labels average working oximeters and include **240 evaluation windows below 70%**, unlike the original paper's stated lower-range exclusion. Coarse 100 s pooled time balancing does not remove within-bin time, person, drift or protocol confounding. “Clock-free” and clinical generalization are unsupported.

## 2. Novelty

**Phone-camera low-oxygen detection is not new.** Qualify the write-up's “Our own idea.”

- [Hoffman et al., 2022](https://www.nature.com/articles/s41746-022-00665-y) already demonstrated fingertip camera/flash hypoxemia screening, induced desaturation and subject-held-out testing. Their abstract reports **81% sensitivity/79% specificity below 90%** and **5.00-point SpO₂ MAE**. Their protocol differs; these are not a direct performance comparison.
- [Samavati et al./MTHS](https://arxiv.org/abs/2204.08989), with [author code/data](https://github.com/MahdiFarvardin/MEDVSE), already studied efficient smartphone vital estimation and supplied **62 recordings**, RGB at **30 Hz**, HR/SpO₂ at **1 Hz**. A largely normoxic cohort cannot settle hypoxemia detection.
- Ratios, calibration and physiological filtering predate this app. [Sun et al., 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC7984770/) used smartphone RGB/red-green ratios with calibrated regression; [Tian et al., 2022](https://doi.org/10.1109/JSTSP.2022.3152352) used multichannel ratios and HR-adaptive filtering. These noncontact setups differ from this fingertip capture. A failed ratio variant here does not invalidate prior camera oximetry.

**What is added:** a small personalized classifier, causal JavaScript implementation, browser capture/replay, abstention and a confound audit. Useful engineering/reproducibility work. No demonstrated new sensing principle, first hypoxemia detector, or superiority to prior work.

## 3. Measurement logic: blocker and top five wrong-answer paths

**Release blocker by code inspection:** `app.js` captures `gen = camGen`, calls `startCamera()` (which increments `camGen`), then executes `if (gen !== camGen) return`. Even if camera startup succeeds, that return occurs before `setup-live.hidden = false`. Separately, the default synthetic-camera run here hits “Requested device not found” and times out waiting for setup; it does not dynamically establish the generation bug. **Fix:** separate session cancellation from camera-instance generation and test the complete probe→start→setup transition. Unit lens/stall tests miss this integration bug.

Once that blocker is fixed:

1. **Already hypoxic at calibration → “Normal.”** `engine.js::_window` subtracts the first minute without knowing oxygen status. Starting at altitude or restarting during illness can normalize the dangerous state. **Fix:** require an independently established baseline for oxygen interpretation; otherwise say “oxygen status unknown,” including after restart.
2. **HR changes for the wrong reason → false alarm, or no HR response → missed hypoxemia.** Stationary exertion recovery, anxiety, caffeine, beta-blockers and arrhythmia are not detected by a still-phone check; missing motion data defaults to not moving. **Fix:** enforce and validate recovery/stability checks, reject unsupported conditions, and describe an HR-change alert until oxygen specificity is established.
3. **Rejected live samples poison calibration → later confident error.** Engine `calRows` uses pulse validity, not live placement/motion/timing masks. `checkCalibration` has no finger-coverage requirement; exposure adaptation can also run after calibration starts. **Fix:** collect baseline only from contiguous samples passing all acquisition gates; complete exposure setup first; reset on finger replacement or settings changes.
4. **Different camera/light/pressure → wrong feature deltas.** Locks are best effort and not verified from actual settings; ambient/front-camera fallbacks still run a model trained on locked Nexus 6P fingertip/flash recordings. New stall gates address interruptions, not this domain shift. **Fix:** restrict answers to validated acquisition modes, verify settings, detect pressure/exposure steps and require new calibration after changes. Obtain paired phone/oximeter validation per mode/device.
5. **Confident wrong pulse → confident wrong oxygen class.** Spectral/ACF agreement can accept a harmonic or artifact; BUT still shows substantial accepted errors and halving. The app's probability band is not calibrated clinical uncertainty, and the extra engine beat gate lacks equivalent independent error reporting. **Fix:** test the full engine against ECG, add morphology/cross-channel and harmonic checks, expand slow-pulse testing, and withhold oxygen interpretation when pulse uncertainty is material.
