End-to-end browser test of the **live camera path** with synthetic fingertip videos (no real camera needed), plus the recorded-demo (replay) path.

```bash
python3 tests/e2e/make_fake_video.py good fake_good.y4m     # 72 bpm pulse on a red-dominant frame (pure Python)
python3 tests/e2e/make_fake_video.py bad  fake_bad.y4m      # grey noise, no finger
npm i playwright-core                                       # or point PLAYWRIGHT_CORE at an existing playwright-core/index.mjs
CHROME=/path/to/chromium node tests/e2e/fake_camera.mjs     # serves app/ itself on a random local port
```
Set `LIVE_URL=https://aravhawk.github.io/oxydrop/index.html` to run the cases against the deployed site instead of the local copy (an earlier note here said the `good` case passed against the live site after the v2 deploy; the review could not reproduce that, the cause was the setup-screen generation-guard bug fixed in this branch, and the live site has to be redeployed from this branch before it is re-run there).

Engine under test (`ENGINE=`): unset runs the app's default engine with no query string (PhotonDistill since FEAT-006); `ENGINE=logistic` and `ENGINE=hybrid` add `?engine=`; `ENGINE=distill` names the default explicitly. The engine-specific assertions follow the engine (the `replaylog` case always runs `?engine=logistic`).

Cases (`CASES=good,bad,replay,replaylog,stall,calstall`, default all; the default engine, PhotonDistill, runs in the page thread; the hybrid CNN runs in a Web Worker):
* **good**: lens select, ambient/flash toggle, placement reaches "Fingertip detected", Start enables after 3 locked windows, 60 s calibration passes, heart rate 72 +-6 (spectral estimate; the hybrid CNN head reads 4 to 5 bpm high on this synthetic pulse), zero console errors, debug CSV download and copy work. Engine-specific: **distill** the debug view names `engine oxydrop-photon-distill-v1 ... 2,435 parameters per seed (7,305 in total), runs in the page thread`, shows the model line (raw P(SpO2<90), abstain flag, abstain-head confidence, latency, experimental SpO2 estimate labelled "not validated"), the state card equals the model line (abstain -> "Unsure, re-measure", P > 0.5 -> "Possible low oxygen", else "Normal vs your baseline") and every row of the debug CSV is either the model's answer or carries a measurement-validity reason (camera stalled, calibration failed, no finger, moving, low fps, frame gaps); **logistic** the engine line names the v2 chain and the state is Normal; **hybrid** the hybrid engine line (167,588 parameters per seed, Web Worker, conformal alpha 0.1) and state Normal.
* **bad**: the placement check refuses a grey frame, "Start anyway" appears after 20 s, the result is "Unsure, re-measure" and the heart-rate tile shows an en dash.
* **replay**: recorded Hoffman demo in the page thread; the note must say "Model trained on this person: demo only, not a test" (the final weights saw these participants). hybrid / logistic: participant 4 (resting 43 bpm, below the 51 bpm band edge, so the pulse-lock gate never opens) must be "unsure" throughout. distill: no pulse-lock gate exists, the check is that the debug CSV audit finds only model answers and validity reasons and that the last state equals the last model line; the tally is printed (it is a demo on training people, never an accuracy number).
* **replaylog**: the same recordings with `?engine=logistic` (v2 logistic chain, weights fitted without that person, the baseline of the comparison).
* **stall**, **calstall**: a camera stall after calibration flips the answer to Unsure within 2.6 s and recovers; a stall inside the calibration minute rejects it. These cases run in real time, so they flake when the machine is starved (load average far above the core count): the wall-clock stall rule then fires on its own. Run them on a quiet box, one Chromium at a time.

Takes about 6 minutes in real time (the camera runs at real speed). If Chromium crashes at start with "disk I/O error", `/tmp` is full: set `TMPDIR` to a directory on disk.
